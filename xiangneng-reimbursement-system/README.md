# 祥能报销系统 · 可交互原型 V0.2

这是根据已确认业务流程制作的**可交互、数据联动的前端原型**，用于业务验证和后续 Codex 全栈开发。

> 当前版本不是生产系统。它使用浏览器 `localStorage` 保存演示数据，OCR 为本地规则模拟，附件为浏览器端压缩预览。

## 已实现

### 报销人端

- 底部导航固定为：记录、进度、明细；
- 项目非必填；
- 发票与付款凭证支持多附件；
- 根据文件名模拟识别发票类型和金额，可人工修改；
- 明细可筛选、点击下钻查看附件；
- 发票金额必须严格大于报销金额才能提交批次。

### 部门制单端

- 自动生成表1：费用类型、付款金额、发票金额；
- 自动生成表2：报销人、报销总金额；
- 自动生成表3：序号、报销人、使用用途、付款金额、发票金额；
- 三张表可导出 CSV；
- 付款凭证和发票分开生成打印包；
- 附件顺序与表3稳定序号一致。

### 审核与付款

- 负责人整批审核；
- 财务自动校验三张表、金额覆盖和附件完整性；
- 问题标记不改变主状态，解决后才能继续审核；
- 付款清单直接复用表2；
- 支持审核通过、待打款、已打款完整七态流转；
- 所有角色共享同一批次数据，操作后实时联动。

## 本地运行

```bash
npm run dev
```

浏览器打开：`http://127.0.0.1:5173`

## 验证

- 全部 JavaScript 文件语法检查；
- 七类主要视图运行时模板生成检查。

## 数据联动说明

唯一数据源为 `state.batch.details`：

```text
报销人新增明细
→ 报销人批次汇总实时更新
→ 部门表1/表2/表3实时更新
→ 两套打印包实时更新
→ 负责人看到同一批次明细
→ 财务自动校验同一批次数据
→ 付款清单复用表2结果
```

任何汇总表都不是独立手工数据。

## 当前边界

- 数据仅保存在同一浏览器的 `localStorage`；
- 无正式登录、数据库和服务器权限隔离；
- OCR 仅根据文件名进行规则模拟；
- 附件预览保存在浏览器端，较大文件可能受存储空间限制；
- CSV 导出与浏览器打印已实现，正式 XLSX/PDF 模板待全栈阶段完成；
- 真实发票验真、银行付款、审计日志持久化尚未接入。
